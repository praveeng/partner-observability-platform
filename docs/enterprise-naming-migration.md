# Enterprise Naming Migration

## Decision and scope

Partner Observability Java code uses the mandatory package root
`com.samsung.sure.partner.observability.*`. Java/Spring Gradle modules and their artifact IDs use
`sure-partner-observability-*`, and the Gradle group is `com.samsung.sure`. This is an intentional
breaking source/package migration: no compatibility package, alias, wrapper, or forwarding type is
provided under the former Java namespace.

Public `partner-observability.*` Spring configuration properties, telemetry record and metric
names, Loki/Prometheus semantics, and established synthetic runtime `service.name` values are not
Java package or module coordinates and remain unchanged.

## Module and consumer contract

The four Java/Spring modules are:

- `sure-partner-observability-core`
- `sure-partner-observability-spring-boot-autoconfigure`
- `sure-partner-observability-spring-boot-starter`
- `sure-partner-observability-test-app`

The supported partner-service dependency is:

```groovy
dependencies {
    implementation 'com.samsung.sure:sure-partner-observability-spring-boot-starter:0.1.0-SNAPSHOT'
}
```

`EnterpriseNamespaceStarterConsumerIntegrationTest` compiles through that starter project
dependency using only Samsung Sure imports, starts the Spring Boot 2.7 application context, and
asserts configuration properties, explicit/callback hooks, bounded health, all three HTTP client
fixtures, and Micrometer registration.

## Permanent enforcement

`scripts/test-enterprise-naming.sh` rejects legacy package declarations/imports, legacy source
directories, package-to-path mismatches, legacy Spring resource references, legacy top-level module
directories, stale Gradle includes/project dependencies/tasks/build paths, a non-enterprise Gradle
group, or a missing required module. `scripts/verify-all.sh` runs this check before compilation.

## Preserved runtime identifier

The literal `partner-observability-test-app` remains only as the established synthetic application
and telemetry `service.name`/OTel scope identity in the application configuration, Alloy allowlist,
publisher scope, and end-to-end queries. It is not a Gradle module, artifact, dependency, source
path, or Java package reference. Preserving it avoids an unrelated telemetry contract migration.
